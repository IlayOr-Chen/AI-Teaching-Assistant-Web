## 1. Testing Philosophy & Deterministic Isolation

Our testing strategy enforces **100% class-by-class alignment** between our **Low-Level Class Diagram** ([05_architecture_and_diagrams.md](file:///c:/Users/ILAYO/Documents/Projects/AI-Teaching-Assistant-Web/docs/05_architecture_and_diagrams.md)) and our automated `pytest` suite (`tests/`):

1. **Zero Production Firebase Pollution (`InMemoryFirebaseAdapter`):** Every unit and HTTP integration test injects `FirebaseRepository(use_mock=True)`, routing all hierarchical RTDB operations (`get`, `set`, `update`, `push`, `delete`, `reset_mock`) to an isolated, thread-safe in-memory tree with deep-copy isolation.
2. **Deterministic Time & Transport Injection:** Time-sensitive rules—including the `8s + 7s = 15s` rotating QR grace window, the `900s` (15-minute) device cooldown, and homework submission deadline gates—accept an explicit `now_ts` UNIX timestamp parameter so boundary transitions are tested deterministically without `time.sleep()`.
3. **Real-World Course Asset Benchmarks:** Dedicated tests run directly on the three course evaluation assets in `/assets/` (`courseid_130158_participants.xlsx`, `p3.jpeg`, and `Example_ Class  by zoom).docx`).
4. **Automated Diagram-to-Code & Docstring Verification:** [test_architecture_and_edge_cases.py](file:///c:/Users/ILAYO/Documents/Projects/AI-Teaching-Assistant-Web/tests/test_architecture_and_edge_cases.py) uses Python's `inspect` module to assert that all **13 OOP classes** and all **104 methods** match the Low-Level Class Diagram 100% and include explicit `Purpose:`, `Inputs:`, and `Outputs:` docstrings.
